⚠️ Impossible de collecter des offres cette semaine

Raison : L'agent Hermes qui exécute ce cron ne dispose pas d'outils de navigation web (pas de recherche Google, LinkedIn, GitHub, Twitter/X, ni aucun accès HTTP/HTTPS). Les seuls outils disponibles sont :

  • read_file — lecture de fichiers locaux
  • write_file — écriture de fichiers locaux
  • patch — édition de fichiers
  • search_files — recherche dans les fichiers locaux (ripgrep)

Aucun de ces outils ne permet d'accéder à Internet pour rechercher des offres, vérifier des contacts, ou naviguer sur LinkedIn, pages carrières, GitHub, HN, etc.

Pour que ce radar fonctionne, l'agent cron a besoin d'au moins un outil de recherche web (type web_search, browser, fetch_url, ou tavily_search).

📋 Recommandations pour rétablir le radar

Voici les actions à entreprendre pour que le cron du lundi matin produise un radar utile :


1. Ajouter un outil de recherche web à Hermes — NON DISPONIBLE

Configurer un plugin ou skill Hermes avec accès à une API de recherche (Tavily, SerpAPI, Brave Search, etc.) ou un navigateur headless pour que l'agent puisse interroger LinkedIn, Google, pages carrières et GitHub.

Doc : https://hermes-agent.nousresearch.com/docs

2. Fournir un fichier de sources pré-compilées — POSSIBLE

Déposer dans /workspace/ un fichier sources_radar_sXX.json contenant les URLs à scraper + les contacts déjà identifiés. L'agent pourra le lire via read_file et générer le dashboard.

3. Utiliser un fournisseur de modèle avec accès web natif — RECOMMANDÉ

Certains fournisseurs via OpenRouter (comme les modèles avec web_search intégré) ou un modèle configuré avec un tool-use pour le browsing pourraient résoudre ce problème.

4. Exécuter le radar manuellement — SOLUTION IMMÉDIATE

Lancer une session Hermes interactive (non-cron) avec un profil disposant d'outils web, et demander la génération du radar. Sauvegarder le fichier HTML dans /workspace/.
